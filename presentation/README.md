# Презентация приложения АНСДИМАТ

## Что в папке

| Файл | Что это | Кому |
|---|---|---|
| `ANSDIMAT-case.svg` | Презентация-кейс, 1440 × 6861 | Дизайнеру, в портфолио |
| `ANSDIMAT-ui-kit.svg` | Все 15 экранов, палитра, типографика, радиусы и тени | Заказчику |
| `screens/*.png` | Исходные скриншоты, 1170 × 2532 (3×) | Для сторов и вёрстки |
| `screens/opt/*.jpg` | Ужатые копии для вставки в SVG | Служебное |
| `hero-opt.jpg` | Готовый hero-кадр: телефон на бетоне | Для обложек и соцсетей |
| `capture.js` · `compose-hero.js` · `optimize.js` · `build.js` | Конвейер сборки | Разработчику |

## Как открыть в Figma

1. Перетащите `.svg` в холст Figma — или **File → Place image**.
2. Текст останется текстовыми слоями, плашки — прямоугольниками.
3. Поставьте до импорта **Manrope** и **JetBrains Mono** с Google Fonts,
   иначе Figma подменит их системными и метрики поедут.

Корпус телефона, Dynamic Island, статус-бар и полоса жеста нарисованы
векторно и лежат в одной группе со скриншотом: их можно перекрасить или
заменить своим мокапом, не трогая содержимое экрана.

## Как пересобрать

Нужен работающий веб-сервер приложения:

```bash
npx expo start --web
```

Дальше четыре шага. `CHROME_PATH` указывает на уже установленный браузер —
`playwright-core` своих не скачивает.

```bash
export CHROME_PATH="$HOME/Library/Caches/ms-playwright/chromium-1228/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing"
node presentation/capture.js        # снимает 15 экранов в 3×
node presentation/compose-hero.js   # кладёт главный экран на предметный мокап
node presentation/optimize.js       # ужимает картинки под вставку в SVG
node presentation/build.js          # собирает оба SVG
```

`capture.js` сам заводит демонстрационные данные, если их нет: журнал откачки
на 9 замеров, журнал восстановления и три точки дневника.

Для `compose-hero.js` нужен исходный рендер предметной сцены в
`presentation/hero-source.png` (3680 × 2760). Углы экрана телефона на этом
рендере заданы константой `CORNERS` — при смене сцены править только их.

Тексты, факты и подписи блоков лежат константами в начале `build.js` —
правьте там, а не в готовом SVG.

## Про качество и вес

Съёмка идёт в 3× (1170 × 2532), потому что в макете экран занимает
290–390 px и кадр 1× выглядит мылом. В SVG встраиваются ужатые копии:
800 px по ширине, JPEG 0.94 — двойной запас по чёткости при вменяемом весе.
Без этого шага файл кейса раздувается до 10 МБ, и Figma открывает его через силу.

Заодно `optimize.js` снимает цвет верхней строки каждого кадра в
`screens/opt/top-colors.json` — из него берётся цвет статус-бара в мокапе,
чтобы полоса продолжала шапку приложения. Поэтому шаг обязателен: без него
`build.js` соберётся, но статус-бары останутся без цвета.

## Что показано в кейсе

- **Шапка и hero** — название и главный экран на предметном мокапе
- **Факты** — платформы, стек, объём работы
- **Задача → Решение** — как обрабатывали откачку раньше и как теперь
- **Четыре блока экранов** — обработка ОФР, калькулятор, поле и обучение, аккаунт

Данные на скриншотах не выдуманы: журнал «Скв. 12» посчитан по методу
Купера — Джейкоба (T = 158,13 м²/сут при Q = 864 м³/сут и наклоне 1,0 м/цикл),
восстановление уровня по тому же опыту даёт T = 158,35 м²/сут.
