## 1. Что важно понять до начала

**`expo start` — это не сборка.** Он поднимает сервер разработки, а код грузится
в приложение Expo Go. Так нельзя отдать проект заказчику и нельзя проверить
работу без вашего компьютера в той же сети.

**Приложение уже не влезает в Expo Go.** В нём есть `expo-sqlite`,
`react-native-maps`, `expo-location`, `react-native-view-shot` — модули с
нативным кодом. Expo Go содержит фиксированный набор нативных библиотек, и
собранные под него сборки этот проект попросту не запустят. Значит, нужна
собственная сборка.

**Два пути сборки:**

| | EAS Build (облако) | Локально |
|---|---|---|
| Android APK | нужен только аккаунт Expo | нужен Android SDK + JDK |
| iOS для симулятора | нужен только аккаунт Expo | нужен Mac с Xcode |
| iOS на живой iPhone | нужен Apple Developer, $99/год | тоже нужен, плюс Mac |
| Скорость первой сборки | 10–25 минут в очереди | 5–15 минут, но час на настройку |
| Стоимость | 30 сборок в месяц бесплатно | бесплатно |

Дальше по умолчанию идёт облачный путь — он короче и не зависит от того, что
установлено на машине.

**Про iOS сразу, чтобы не было сюрприза.** Поставить сборку на чужой iPhone
без учётной записи Apple Developer ($99 в год) нельзя — это ограничение Apple,
а не проекта. Обходных путей три, все описаны в разделе 5, и у каждого своя
цена.

## 2. Подготовка окружения

### Аккаунт Expo

Бесплатный, регистрация на expo.dev. Проект уже привязан к организации
`omnion` и к `projectId` в `app.json` — если у вас нет доступа к этой
организации, поменяйте `owner` и удалите `extra.eas.projectId`, тогда при
первой сборке создастся новый проект.

```bash
npm install -g eas-cli
eas login
eas whoami
```

### Зависимости проекта

```bash
npm install
```

### Проверка перед сборкой

Сборка в облаке занимает 10–25 минут, поэтому дешевле отловить проблемы до неё:

```bash
npx expo-doctor
npx jest
```

`expo-doctor` ловит несовместимые версии библиотек — самую частую причину
падения сборки. Если он предлагает `npx expo install --fix`, соглашайтесь:
версии нативных модулей должны соответствовать версии SDK.

## 3. Ключи Supabase в сборке

Файл `.env` в git не попадает, но на сборочный сервер EAS уезжает вместе с
проектом: `.easignore` его намеренно не исключает. Поэтому достаточно, чтобы
`.env` лежал в корне проекта на той машине, с которой запускается
`eas build`, — адрес Supabase и anon-ключ попадут в сборку сами.

Без ключей приложение соберётся и запустится, но аккаунты и синхронизация
работать не будут: вход ответит «Синхронизация не настроена». Именно так
выходили облачные сборки, пока `.env` был в `.easignore`.

Адрес и ключ берутся в облачном проекте Supabase: Project Settings → API.
Как завести бесплатный проект — в [docs/supabase/README.md](./supabase/README.md).

**Бесплатный проект Supabase засыпает после недели без запросов**, и его адрес
перестаёт отвечать — вход в приложении выглядит как «нет связи с сервером».
Разбудить его — кнопка Restore project в панели Supabase.

В `.env` — только `EXPO_PUBLIC_*`. Серверные ключи держите в `.env.local`:
он на сборочный сервер не уезжает.

**Локальный Supabase (`127.0.0.1:54321`) в сборку класть бессмысленно**: для
телефона это его собственный адрес, а не ваш компьютер. Для теста на устройстве
нужен либо облачный проект, либо адрес машины в локальной сети.

`anon`-ключ публичный и лежит в бандле открыто — так и задумано. Данные
закрывают политики доступа в базе, а не секретность ключа. А вот
`service_role` в приложение класть нельзя никогда: он обходит все политики.

## 4. Android: APK для заказчика

Одна команда:

```bash
eas build --platform android --profile preview
```

Что происходит: EAS запрашивает разрешение создать ключ подписи (соглашайтесь,
он останется в вашем аккаунте), собирает проект и выдаёт ссылку на `.apk`.

Профиль `preview` в [eas.json](../eas.json) задаёт именно APK. Это важно:
профиль `production` по умолчанию во многих проектах собирает `.aab` — формат
для загрузки в Google Play, который нельзя установить на телефон напрямую.

**Как поставить на телефон.** Скачать APK по ссылке из письма или из личного
кабинета expo.dev, открыть файл, разрешить установку из неизвестных источников.
Android покажет предупреждение о неизвестном разработчике — это нормально для
сборки вне магазина.

**Что отправить заказчику.** Ссылку из EAS: она ведёт на страницу с QR-кодом,
телефон скачает файл сам. Пересылать APK мессенджером хуже — многие сжимают
вложения и ломают файл.

Ссылки EAS живут ограниченное время. Для долгого хранения скачайте APK и
положите куда-нибудь к себе.

**Отслеживание сборки:**

```bash
eas build:list --platform android --limit 5
```

## 5. iOS: три варианта

Разница только в том, есть ли платная учётная запись Apple Developer.

### Вариант А. Симулятор — без Apple ID, но и без живого телефона

```bash
eas build --platform ios --profile simulator
```

На выходе `.tar.gz` с `.app` внутри. Разворачивается на Mac:

```bash
tar -xzf <файл>.tar.gz && xcrun simctl install booted Ansdimat.app
```

Годится, чтобы показать приложение на встрече со своего ноутбука. Не годится,
чтобы дать заказчику потрогать на своём телефоне: симулятор бывает только на
Mac, GPS в нём поддельный, а карта и камера ведут себя иначе.

### Вариант Б. Ad hoc — на конкретные iPhone, нужен Apple Developer

Подходит, когда устройств немного и вы знаете их заранее.

```bash
eas device:create
```

Команда выдаёт ссылку или QR-код: владелец iPhone открывает его на своём
телефоне и ставит профиль — так его устройство регистрируется в вашей учётной
записи. Потом:

```bash
eas build --platform ios --profile preview
```

Сборка встанет только на зарегистрированные устройства, лимит — 100 в год.
При добавлении нового устройства нужна новая сборка: список зашивается внутрь.

### Вариант В. TestFlight — правильный способ отдать на тест

Тоже требует Apple Developer, зато заказчику не нужно ничего регистрировать —
достаточно почты.

```bash
eas build --platform ios --profile production
```

```bash
eas submit --platform ios --latest
```

Дальше в App Store Connect добавляете тестировщиков, они ставят приложение
через TestFlight. Внутренним тестировщикам (до 100 человек) сборка доступна
сразу, внешним (до 10 000) — после проверки Apple, обычно сутки-двое.

Сборка в TestFlight живёт 90 дней.

**Рекомендация.** Если Apple Developer уже оплачен — сразу TestFlight: заказчик
получает обновления сам, без пересылки файлов. Если нет и покупать пока рано —
Android APK для заказчика, iOS-симулятор для показа со своей машины.

## 6. Локальная сборка без облака

Имеет смысл, когда лимит бесплатных сборок исчерпан или нужно собирать часто.

### Android

Нужны JDK 17 и Android SDK (проще всего поставить Android Studio).

```bash
npx expo prebuild --platform android --clean
```

```bash
cd android && ./gradlew assembleRelease
```

APK окажется в `android/app/build/outputs/apk/release/`.

`prebuild` создаёт каталог `android/` из конфигурации `app.json`. Каталог
одноразовый: правки в нём затираются при следующем `prebuild`, поэтому всё,
что нужно сохранить, задаётся через `app.json` и плагины Expo.

### iOS

Нужен Mac с Xcode.

```bash
npx expo prebuild --platform ios --clean
```

```bash
cd ios && pod install
```

Дальше открыть `ios/Ansdimat.xcworkspace` в Xcode и собрать оттуда. Для запуска
на живом устройстве всё равно понадобится учётная запись разработчика — Xcode
даёт бесплатную подпись на 7 дней, после чего приложение перестаёт
запускаться.

### Через EAS, но на своей машине

```bash
eas build --platform android --profile preview --local
```

Тот же рецепт сборки, что в облаке, но выполняется локально: результат
воспроизводим, лимит не тратится.

## 7. Разработка на телефоне

Для повседневной работы собирать APK на каждое изменение не нужно. Один раз
собирается клиент разработки, дальше код прилетает в него по сети:

```bash
eas build --platform android --profile development
```

```bash
npx expo start --dev-client
```

Пересборка нужна только при добавлении новой нативной библиотеки или смене
разрешений — то есть всего, что меняет нативную часть.

## 8. Перед публикацией в магазины

Тестовая сборка и магазинная — разные вещи. Что нужно доделать:

**Обязательно.**

- Формат Android. В `eas.json` профиль `production` сейчас собирает APK.
  Google Play принимает только `.aab` — перед первой публикацией поменяйте
  `buildType` на `app-bundle`. Для APK-раздачи заказчику остаётся `preview`.
- Оплата подписок. Магазины не разрешают продавать доступ мимо своей платёжной
  системы. Сейчас кнопка «Подписаться» честно объясняет, что оплата
  подключается, и предлагает промокод — для теста это нормально, для релиза
  нужен биллинг. Схема к нему готова, см. [docs/backend-plan.md](./backend-plan.md).
- Политика конфиденциальности по публичному адресу. Требуют обе площадки,
  потому что приложение собирает почту и координаты.
- Возрастной рейтинг и описание сбора данных: анкета Data Safety в Google Play,
  App Privacy в App Store Connect.

**Уже сделано.** Удаление аккаунта прямо из приложения — обязательное
требование обеих площадок; работает на экране «Аккаунт».

**Стоит проверить.** Иконки и сплэш во всех плотностях, поведение без сети,
запрос геолокации при отказе в разрешении.

## 9. Частые ошибки

**`Cannot determine which native SDK version your project uses`** — не
установлены зависимости. `npm install`.

**Сборка падает на этапе установки зависимостей** — рассинхрон версий нативных
модулей с версией SDK. `npx expo install --fix`, потом `npx expo-doctor`.

**APK ставится, но приложение падает при запуске** — чаще всего отсутствует
переменная окружения, на которую код рассчитывает. Смотрите логи:

```bash
adb logcat | grep -i ansdimat
```

**Аккаунты и синхронизация не работают в сборке** — «Синхронизация не
настроена»: на машине, с которой запускали сборку, не было `.env`, см.
раздел 3. «Нет связи с сервером» при живом интернете: проект Supabase уснул
или удалён — проверьте его в панели Supabase.

**iOS-сборка требует пароль от Apple ID** — EAS сам создаёт сертификаты и
профили, для этого ему нужен вход в вашу учётную запись Apple. Если делать
это через веб-интерфейс EAS не хочется, сертификаты можно сгенерировать
вручную и загрузить через `eas credentials`.

**`Build failed: Unknown error`** без деталей — откройте полный лог по ссылке
из вывода команды: `eas build:list` даёт адрес страницы сборки, там есть
вывод каждого шага.
