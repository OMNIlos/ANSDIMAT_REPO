# Три вида прослеживания и пьезопроводность

Определение фильтрационных параметров способом прямой линии по трём видам
прослеживания — временнóму, площадному и комбинированному — и расчёт
пьезопроводности `a` по каждому из них.

Источник: АНСДИМАТ, 2-е издание, разд. 4.1.1 «Способ прямой линии»,
табл. 4.1 и 4.2 (печатные стр. 310–311). В 1-м издании те же таблицы идут
номерами 13.1 и 13.2.

## Что даёт каждый вид

`C = tg α` — угловой коэффициент прямой, `A` — отрезок на оси ординат.

| | временнóе | площадное | комбинированное |
|---|---|---|---|
| График | `s — lg t` | `s — lg r` | `s — lg(t/r²)` |
| Зависимость | `s = C·lg t + A` | `s = −C·lg r + A` | `s = C·lg(t/r²) + A` |
| Проводимость | `T = 0.183·Q/C` | `T = 0.366·Q/C` | `T = 0.183·Q/C` |
| Пьезопроводность | `lg a = A/C + lg(r²/2.25)` | `lg a = 2A/C − lg(2.25·t)` | `lg a = A/C − lg 2.25` |

Водоотдача берётся из табл. 4.2 — по отрезку `x`, который прямая отсекает на
оси абсцисс: `S = 2.25·T·t_x/r²`, `S = 2.25·T·t/r_x²`, `S = 2.25·T·(t/r²)_x`.
Все три сводятся к `S = T/a` — это определение пьезопроводности, а не второй
вывод, поэтому в коде считается `S = T/a`, а совпадение с отрезком на оси
проверяется тестом. Сверка идёт с книгой, а не расчёта с самим собой.

## Поправка на минуты — главное место

Формулы таблицы написаны для времени в **сутках**, журнал ОФР ведётся в
**минутах**, и регрессия идёт по `lg t` в минутах.

`C` к смене единицы времени нечувствителен: он берётся на логарифмический
цикл, а смена единицы сдвигает `lg t` на постоянную. Поэтому `T` считается
верно и сейчас. Свободный член сдвигается: `A_сут = A_мин + C·lg 1440`.

Отсюда рабочие формулы:

- временнóе: `lg a = A_мин/C + lg 1440 + lg(r²/2.25)`
- комбинированное: `lg a = A_мин/C + lg 1440 − lg 2.25` (тот же сдвиг: в
  `lg(t/r²)` время входит так же)
- площадное: `t` входит в формулу явно и подставляется в сутках — `t_мин/1440`
- отрезки на оси абсцисс (`t_x`, `(t/r²)_x`) снимаются в минутах и делятся
  на 1440

Без поправки `lg 1440 ≈ 3.158` пьезопроводность выходит ровно в 1440 раз
меньше. На глаз это не видно: `a` меняется на порядки от пласта к пласту, и
неверное значение выглядит правдоподобно. Поэтому нужен тест именно на
размерность — модельная откачка с известными `T` и `S` и проверка `a = T/S`.

## Расчётный слой

Зависимость односторонняя: `tracking.js` → `cooperJacob.js`.

**`calc/cooperJacob.js`** — временнóе прослеживание: это и есть метод
Купера — Джейкоба, он уже здесь.

- `diffusivityFromIntercept(slope, intercept, r)` — новая;
- `processDrawdown` отдаёт ещё `a`, а `S` оживает: экран наконец передаёт `r`;
- обе принимают необязательную `line` — прямую, проведённую вручную по двум
  точкам вместо регрессии.

**`calc/tracking.js`** — новый файл, два вида с `r` в абсциссе:

```
TRACKING_KINDS = { TIME, AREA, COMBINED }
processAreaTracking({ points, Q, time, line })
processCombinedTracking({ points, Q, line })
```

`points` — `[{ x, s }]` в базовых единицах, где `x` — сырая абсцисса
(расстояние в метрах или `t/r²` в мин/м²); логарифм берётся внутри.
Обе функции отдают ту же форму, что `processDrawdown`:
`{ slope, intercept, r2, count, T, S, a, applicable, note }` — экрану всё
равно, какой вид открыт.

У площадного два отличия, на которых легко ошибиться: множитель `0.366`
вместо `0.183` и обратный знак наклона — `s` убывает с ростом `r`, поэтому
`C = −slope`.

## Экран

**Переключатель** — одна строка чипов, `lg r` и `lg t/r²` показываются только
у кустовой откачки: остальные виды ОФР расстояний не хранят вовсе.

```
[ lg t ] [ t ] [ √t ] [ lg r ] [ lg t/r² ]
```

Пять чипов в одну строку не влезают — строка получает перенос. Состояние
`xMode` из трёх значений заменяется одним `graphMode` из пяти, `xMode`
выводится из него: два состояния пришлось бы держать согласованными руками.

**Точки** — из журналов всех скважин с `distance > 0`; опытная входит наравне
с наблюдательными по своему `r₀`. Лишнюю точку геолог отбрасывает сам, ведя
прямую по двум выбранным.

| вид | точки |
|---|---|
| `lg t` | замеры открытой скважины, `r` — её расстояние |
| `lg r` | по точке на скважину на выбранный момент, `x = r` |
| `lg t/r²` | все замеры всех скважин, `x = t/r²` |

**Момент времени** для площадного — строка чипов с теми `t`, что есть хотя бы
у двух скважин. Совпадение по замеру, а не интерполяция: точка площадного
графика — это снятый отсчёт, а не восстановленное значение. Ключ группировки
— `roundBase(t)`, тем же округлением, каким замер лёг в базу, иначе полчаса,
введённые как «0.5 ч» и как «30 мин», разошлись бы в последнем разряде. Общего
момента нет — вместо пустого графика текст, чего не хватает.

**Прямая для чисел считается на экране по базовым точкам.** Сейчас наклон и
свободный член берутся из прямой, которую провёл график, а она построена по
точкам в единицах пользователя. Наклону это безразлично, свободному члену нет:
в футах он другой, и `a` уехала бы. График продолжает рисовать свою прямую в
своих координатах — обе совпадают с точностью до сдвига, который график
учитывает сам. Состояние `fit` после этого лишнее и уходит; `awaitingSelection`
выводится из способа построения и числа отмеченных точек.

**Карточки результата** — `T` и `a` в первой строке, `S` и наклон во второй.
`a` показывается в размерности из настроек (`QUANTITIES.DIFFUSIVITY`), `S`
безразмерна и показывается значащими цифрами: 1e-4 в `toFixed(2)` дало бы
0.00. Прочерк объясняется тем же способом, что и у `T`: не введено
расстояние, нет общего момента, меньше двух скважин.

## График

Комбинированному нужен цвет на скважину при одной прямой по всем точкам.
Существующий `extraSeries` не подходит: его точки в подбор прямой не входят.
Точки `measurements` получают необязательные `group`/`groupName` — цвет и
легенда по группе, ломаная своя у каждой скважины, а подбор прямой и отметка
точек остаются по всему массиву, как были.

Площадное остаётся одной серией с ломаной по возрастанию `r`: это профиль
депрессионной воронки, и он читается лучше, чем пять несвязанных цветных
точек.

## Что проверяется

- `calc/__tests__/tracking.test.js` — три вида на модельной откачке по Тейсу с
  известными `T` и `S`; тест на размерность (`a = T/S`, а не в 1440 раз
  меньше); множитель `0.366` и обратный знак у площадного; сверка `S` с
  отрезком на оси абсцисс из табл. 4.2; вырожденные случаи — меньше двух
  точек, нулевой наклон, отсутствующее расстояние.
- `calc/__tests__/roundTrip.test.js` — `T`, `S` и `a` по всем трём видам
  сходятся к одному и тому же пласту.
- Полный набор идёт под Node 22: трём наборам нужен `node:sqlite`, на Node 20
  они молча пропускаются.
- Интерфейс — настоящей веб-сборкой. Babel в тестовой среде понижает `const`
  до `var`, временная мёртвая зона исчезает, и обращение к константе до
  инициализации проходит тесты, роняя экран в белое в браузере.

## Границы

Площадное и комбинированное включаются только у кустовой откачки: без `r` у
каждой скважины их не построить. У одиночной откачки, налива и восстановления
остаётся временнóе прослеживание — как сейчас.
